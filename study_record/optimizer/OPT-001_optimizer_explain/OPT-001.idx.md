# OPT-001 Optimizer / EXPLAIN

- 研究级别：S
- 状态：`✅ 已完成（2026-09-03）`
- 环境：MySQL 8.4.10；PostgreSQL 18.4；专用隔离实例

## 待证明结论

1. MySQL 优化器从逻辑 Query_block 构造访问路径、估算 rows/cost 并选择物理 iterator；EXPLAIN 展示的是该决策结果，不是语法改写摘要。
2. 谓词是否可用于索引改变候选 access path；同样返回一行，`id=常量` 与 `id+0=常量` 会走不同路径。
3. 普通 `EXPLAIN` 只优化不执行；MySQL 8.4.10 的 `EXPLAIN ANALYZE` 会真实执行受支持的查询并补充 actual time/rows/loops，但本次 `UPDATE` 实测返回 `not executable by iterator executor` 且没有修改数据。不同数据库和版本对 DML 的行为不能类推，验证时仍须使用可回滚事务。
4. `optimizer_trace` 能看到候选路径、成本与 chosen/cause，是解释“为什么没走索引”的关键路径证据。
5. PG 与 MySQL 都是 cost-based optimizer，但 EXPLAIN 字段、执行器节点、缓存/IO观测能力及语法不同。
