# REP-001 Binlog Replication + GTID

- 研究级别：S
- 状态：`✅ 已完成（2026-09-03）`
- 环境：MySQL 8.4.10；PostgreSQL 18.4；专用双实例

## 待证明结论

1. MySQL 异步复制由 source binlog、replica receiver、relay log、applier 分段推进，并非 source 直接修改 replica 数据页。
2. GTID auto-position 用双方集合差异选择缺失事务，连接配置无需固定 file/position。
3. receiver 与 applier 生命周期独立；暂停 SQL_THREAD 时仍可接收 binlog，恢复后从 relay log 追平。
4. `SOURCE_AUTO_POSITION=1` 依赖 source 保留所需 GTID 对应 binlog；GTID 集合不是事务内容本身。
5. PG physical streaming replication 与 MySQL binlog replication 都有 sender/receiver/replay，但复制粒度、身份和可观测状态不同。
