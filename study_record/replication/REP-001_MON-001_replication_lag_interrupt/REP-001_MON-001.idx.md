# REP-001 + MON-001 Replication Lag / Interruption

- 研究级别：S
- 状态：`✅ 已完成（2026-09-03）`
- 环境：MySQL 8.4.10；PostgreSQL 18.4；专用双实例

## 待证明结论

1. 复制健康必须拆成 source→receiver、receiver→relay、relay→applier 三段，`Seconds_Behind_Source` 不能单独定位故障。
2. Source 短时中断使 receiver 重连；applier 可继续消费已有 relay log，恢复连接后按原 GTID 集合续接。
3. MySQL 逻辑 applier 会因副本本地数据分歧触发 1062 等执行错误；receiver 仍可继续接收，造成 Retrieved 与 Executed 分叉。
4. 正确修复是核实并消除数据分歧后重启 applier，不是盲目跳过事务。
5. PG 物理 standby 通过只读约束阻止本地 DML 分歧，但仍需分别诊断 WAL transport 与 replay lag。
