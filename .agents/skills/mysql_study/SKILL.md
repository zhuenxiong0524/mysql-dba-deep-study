# mysql-study — PG → MySQL 对照学习（v0.3）

## 目标

以核心机制深度不下降为前提，用最少但充分的证据完成可信闭环：

```text
待证明结论 → PG 基线 → MySQL 对应机制 → 同构实验 → 源码锚点 → 差异结论 → 学习记录
```

不以文章长度、实验数量或源码摘录量衡量完成度。速度来自批处理、自动化、复用和停止重复取证，
不能靠省略 MySQL 操作步骤或降低关键机制深度获得。

## 模式选择

默认使用**深度快跑**。开始或继续一个专题时，读取
[references/fast-workflow.md](references/fast-workflow.md)。

每个专题先区分：

- **核心机制**：直接决定 PG→MySQL 心智迁移的行为，必须解释原因、关键源码路径、边界和生产影响；
- **支撑事实**：版本、参数、对象状态等，只保留验证结论所需的最小证据。

崩溃恢复、复制一致性、备份恢复、性能基准或故障注入等专题可以增加实验强度，但仍遵守证据去重。
任务权重为 L 不意味着所有分支都要展开，只深挖会改变结论的路径。

## 深度快跑的交付预算

以下是默认目标，可因证据需要调整：

- 开始前列出 3～7 条“待证明结论”，后续内容都服务于它们；
- 每个关键差异只做一个最小同构实验，PG/MySQL 各跑一次；
- 每条核心机制保留 1～3 个关键源码锚点，覆盖决策入口、关键分支和必要的执行/错误出口；
- 对照文章通常控制在 160～280 行，必须讲清“为什么、边界、失败形态、生产影响”；
- 原始终端输出去掉提示符噪声、重复查询和无关状态，但不得改写结果；
- `verification/` 默认不创建；仅当用户要求自测或该专题确需检验理解时添加；
- `pg-mysql-map.md` 只增加新的心智映射；
- Runbook 只收录可直接用于生产诊断/处置的新内容，不复述文章；
- roadmap/idx 只记录状态、资产入口和未决项。

超出预算不是错误，但必须由新的结论、风险或可复现性需要驱动。

## MySQL 实操硬性指标

每篇新专题文章必须包含标题完全一致的 `## MySQL 实操：命令与 SQL`，并满足：

1. 给出连接方式、前置条件或对象准备；
2. 给出可以按顺序直接执行的完整 MySQL 命令/SQL，不使用 `...` 代替关键步骤；
3. 标出关键结果、错误码或判断标准，让不熟悉 MySQL 的读者知道是否执行正确；
4. 给出清理、还原或回滚命令；纯只读操作应明确说明无需清理；
5. 涉及多会话时明确标注 T1/T2 和执行顺序；
6. 涉及危险操作时写明影响范围和停止条件。

MySQL 命令还应保存在 evidence 的可复现文件中，文章中的实操章节必须自包含，不能只链接 evidence。

PG 侧仍必须实际执行并留 evidence，保证实验可比；文章可以只写 PG 机制、关键结果和差异，
不强制重复完整 PG 命令/SQL。仅当 PG 语法本身构成迁移差异时才在正文展开。

## 执行原则

1. **先定结论矩阵，再动手。** 为每条结论写清 PG 预期、MySQL 预期、实验观察点和源码入口。
2. **一次准备，多次复用。** 同一专题共享 setup/cleanup；独立只读检查合并或并行执行。
3. **并发实验自动化。** 两会话实验优先使用有界等待、明确同步点和自动收尾的脚本；观察到阻塞证据后主动释放，不等待 lock timeout。
4. **研究并行、结论串行。** 可独立的源码搜索、环境读取和双引擎准备批量或并行执行；先核实结果，再统一写作。
5. **先保存证据，再写文章。** 从同一份结论矩阵派生文章、idx、map 和 runbook，禁止逐份重新研究。
6. **证据按结论裁剪。** 保存版本、命令、关键输出和异常；不整段复制无关源码或完整状态转储。
7. **一次验收。** 新专题运行 `scripts/validate_topic.sh <专题目录>`；历史专题回归可用 `--legacy`。随后清理环境并只做一次 Git 状态检查。
8. **到证据充分即停止。** 所有待证明结论都有双引擎观察或明确“不适用”，核心机制有足够源码链，MySQL 实操可复现，即可完成。

## 不变底线

- 每个重要主题先建立 PG 基线，再研究 MySQL。
- 关键对照实验必须两边各跑一次；不能只抄文档或只跑一边。
- 关键 MySQL 机制必须以本地 8.4.10 源码确认；模型记忆不能代替证据。
- 不伪造或“整理成更好看”的 SQL 结果、执行计划、源码位置和日志。
- `study_record/**` 是累积资产，不覆盖已完成主题，不清空用户内容。
- MySQL 缺失或实现不同的能力明确标为心智地图差异点。
- 机器仅 1C/2G，实验使用保守参数、有界数据量和清理步骤。
- 不自动 commit/push；只有用户明确要求时执行。
